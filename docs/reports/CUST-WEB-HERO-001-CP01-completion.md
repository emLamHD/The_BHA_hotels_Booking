## 1. How to try it (Owner)

1. Pictures need a directory the API can write: `mkdir -p /home/admin1/bha-data/media`, then start the API with `WebsiteMedia__RootPath=/home/admin1/bha-data/media` (local setting only — nothing in code, appsettings or the database holds that path; see the runbook). Apply migration 13 with `dotnet ef database update`.
2. Sign in to Admin (`/signin`) with a Staff account that has the website permission → **Website → Banner trang chủ**.
3. **Tải ảnh lên** (or **Chọn ảnh đã có**) adds a slide; write its alt/caption (Vietnamese and the default language are required; the other languages are optional). **Thay ảnh**, **Xoá**, **Lên/Xuống** work per slide. Choose a language in "Ngôn ngữ đang sửa" to edit the title, description and two button labels per language; choose a font; tick/untick **Tự chuyển ảnh** and set the seconds (3–60). The preview under the form is the draft drawn like the Customer. **Lưu banner** applies everything once; **Huỷ thay đổi** drops the draft; nothing public changes before Save (an uploaded picture is not in the slideshow until Save names it).
4. Keep the Customer home open in another window: the change appears within ≈ 9 s (promise: ≤ 15 s); a new request sees it at once. No rebuild, no restart.
5. Texts also appear in **Website → Bản dịch** under `content.heroSlideshow.main.*` and `content.heroSlide.<id>.*` and travel in exported/imported language packs.

## 4. Findings fixed on the way

- **Browser, 375/768/1440 with the longest text:** the title, description and buttons ran into the slide dots and the caption (a 24-character button label wrapped to two rows; a 100-character caption reached the dots on desktop). → text limits 80 / 160 / 24 / 24 and caption 60; title and description clamp to 2 lines under `lg` (3 and 4 on `lg`); the two buttons stay on one row and shorten with an ellipsis; the caption stays left of the dots on `lg`. The migration was regenerated for the new limits before any merge.
- **Browser:** the Admin slide rows collapsed to one letter per line → the row is now picture/info above, actions below.
- **A pack installed later had no hero texts** (a fresh `fr` was 12 keys short and could not be enabled) → the built-in vi/en/fr packs carry the 12 keys by their stable ids (pack version `2026.10.17`).
- **A deployed Admin proxies only `/api/admin/v1/*`:** pictures on the public route would have 404'd in the editor → the editor reads pictures from the Staff route `/api/admin/v1/website/hero/media/{id}`.
- **Swashbuckle** refused `[FromForm] IFormFile` (every OpenAPI test failed) and MVC's inferred `[Consumes]` answered a wrong body type before the Staff boundary (404, not 415) → plain `IFormFile` parameter and `SuppressConsumesConstraintForFormFileParameters`.
- A body far over the limit gave the framework's generic 400 → `hero-upload-unreadable` on the upload action only.
- The language selector stayed on the language a refusal named; `newId` fallback in the first draft could produce an invalid GUID → fixed, with tests.

## 5. Deviations

- `useLeaveGuard` is now shared by the menu and the hero screens (a move, behaviour unchanged). The menu poller (`createMenuPoller`) and `shouldAcceptMenu` are generic so the hero reuses the same loop (no behaviour change for the menu).
- `ConfigureApiBehaviorOptions` (global, but only affects an endpoint with an `IFormFile` parameter — the hero upload) and a tiny `InvalidModelStateResponseFactory` wrapper that only acts on the marked endpoint.
- The four built-in photographs are **copied** into `TheBha.Infrastructure/HeroMedia/Seed` (embedded resources, 780 KB) so the API serves every picture and the Admin shows the same ones; a Customer test fails if the copies differ from `public/media/the-bha-travel` or lose their credit.
- Admin_Web's root layout loads Poppins and Be Vietnam Pro with `next/font` (self-hosted at build time, same weights/subsets as Customer_Web) only so the preview draws the Customer's letters.

- `HERO_SLIDES`, `HeroSlide` and `localizeHeroSlide` (static slides and their static translations) were removed; the old `content.hero.*` catalog keys stay unused (removing them would change every language's required count).

## 6. Limits and NOT RUN

- **JPEG and WebP pixels are not decoded** (no free decoder dependency): the container is validated (markers/chunks/CRC/inflate/RIFF), so a damaged compressed stream inside a sound container is accepted. Uploads are served as they are (no resizing): keep them near 1920×900 and ≈ 500 KB. No garbage collection of unused uploads; a public picture is reachable by its random id before its Save.
- A direct (non-proxied) Admin on another registrable domain than the API would not send the `SameSite=Strict` Staff cookie with `<img>` requests, so thumbnails would not show there (local development and the proxied deployment are fine).
- No focal-point editor, no per-slide texts or buttons, no colour/size/layout controls, no drag-and-drop (all out of scope).
- NOT RUN: real phones (emulated viewports and touch only); a truly hidden browser tab (simulated); a production or production-like migration and a deploy (forbidden here; the Admin-proxy path is reasoned from `next.config.ts` and the deploy runbook, not run); the full three-route booking regression (no booking or pricing code was touched — only the search form's state, which A4 exercises); Chrome-extension/other browsers; PostgreSQL 18.3 locally (CI runs it).
- The harness is disposable: nothing of it is in the repo; the demo database, the media directory and the servers are left only while the Owner reviews.
