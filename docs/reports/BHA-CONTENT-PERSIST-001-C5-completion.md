## 3. Limits that remain

- Expected, not observed: if a Staff category save is already in flight (children written, its category row not yet) when the importer takes the lock, the two can wait for each other and PostgreSQL ends one with a deadlock (40P01). The importer does not catch it (`TryUpdateAsync` handles only integrity violations), so the command prints `FAILED … The database was not changed` and exits 1 with nothing written; the Staff save would instead get the error and be retried. No test exercises this.
- The lock is taken only for the pack's edited categories that exist on the target; a target category the staff created or edited is never taken over, so it needs none.
- Replacing a pristine menu does not remove the English/French label texts of the items it removes (as before); they are unused rows.
