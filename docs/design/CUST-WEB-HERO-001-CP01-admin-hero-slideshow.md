# CUST-WEB-HERO-001-CP01 — the home page hero edited in the Admin

Status: implemented on `feature/cust-web-hero-001-cp01-admin-slideshow` (Draft PR). Evidence: `docs/reports/CUST-WEB-HERO-001-CP01-completion.md`. Operations: `docs/runbooks/CUST-WEB-HERO-001-hero-media.md`.

## 1. What changed for a person

- **Admin → Website → Banner trang chủ** (`/website/hero`, permission `WebsiteSettingsManage`): the list of slides with thumbnails (upload from the computer, replace, delete, up/down, pick again a picture the site already has), the shared **title, description and two button labels** per language, **one font** for the title and description, an **autoplay switch** and the **seconds between two slides** (whole number 3–60, default 6; it is the time a slide stays, not the length of the fade), and a preview that draws the draft the way the Customer draws it. Edits are a draft: **Lưu banner** applies everything in one transaction, **Huỷ thay đổi** drops it. An uploaded picture is stored at once but is part of the slideshow only after a Save names it.
- **Customer home**: the hero reads the saved configuration on every request and keeps itself current while the home page is open (≤ 15 s; typically ~9 s). Height 380/460/682 px, gradient, text position, the real search form, swipe, credits link and the old photographs' attribution are unchanged.

## 2. Data (migration 13 `AddWebsiteHero`)

Site-wide, not per Property. Three tables, nothing else touched:

| Table | Holds |
|---|---|
| `WebsiteHero` (one row, `Id = 1`) | `Version` (the revision), `FontKey`, `AutoplayEnabled`, `IntervalSeconds`, the four shared texts in Vietnamese (title, description, primary and secondary button), `UpdatedAtUtc/By` |
| `WebsiteHeroSlides` | `Id`, `MediaId` (FK `RESTRICT`), `SortOrder` (unique), `FocalPosition` (CSS `object-position` for narrow screens), the picture's Vietnamese `Alt` and `Caption` |
| `WebsiteHeroMedia` | `Id` (server-generated, part of the public URL), `Kind` `seed`/`upload`, `StorageKey` (relative: `seed/<file>` or `hero/<id>.<ext>`), `ContentType`, `ByteSize`, `Width`, `Height`, who/when. Never edited or deleted by the application |

CHECKs repeat what a row can state alone: singleton, font token, interval 3–60, text lengths, focal shape, storage key shape (no `..`, no absolute path), content type, size. Slide count and "every slide's picture exists" are the Save's, under the website advisory lock.

**Texts are stored content, like menu labels.** The Vietnamese text is the column; every other language's is a `WebsiteTranslations` row keyed by a stable id — `content.heroSlideshow.main.{title|description|primaryAction|secondaryAction}` and `content.heroSlide.<slideId>.{alt|caption}` — listed by `ContentCatalog`, so coverage, the Translations screen, pack export/import and "outdated" work unchanged; the Vietnamese pack never rewrites the columns (`WebsiteLanguagePackService`, same rule as menus). The built-in vi/en/fr packs carry these keys, so a language installed from a pack gets the hero's texts, and a language added later by a pack still works: no enum, no column per locale. Fallback for a visitor: their language's text → the default language's → Vietnamese.

**Seed (once, in the migration, never at startup):** the four photographs in their current order, the current title/description/button texts and each picture's alt/caption in vi/en/fr (taken from the static packs that held them), default font, autoplay on, 6 s, focal positions as before. No hotel claim was added. The old `content.hero.*` and `customer.home.homeHeroCarousel.*` catalog keys stay (removing them would change every language's required count) and are no longer read.

## 3. Pictures

- **Where:** the four built-in photographs are embedded in `TheBha.Infrastructure` (copies of `Customer_Web/public/media/the-bha-travel/hero-*.webp`; a Customer test fails if they differ, and checks every one still has its credit). Uploads are files under `WebsiteMedia:RootPath` — a directory the host provides, outside the source and the build output — written as `hero/<server-generated-id>.<jpg|png|webp>`. Unset: uploads answer `hero-storage-not-configured`, every other thing (and the built-in pictures) keeps working. `IHeroMediaStorage` (Application) is the abstraction; `LocalHeroMediaStorage` (Infrastructure) writes to a temporary name in the same directory, flushes to disk, then renames, so a row never points at a half-written file; keys are matched against two exact shapes and the resolved path must stay under the root.
- **Served by the API**, built-in and uploaded alike. Two read routes, one file behind both: the **public** `GET /api/v1/website/hero/media/{id}` (what the Customer draws: `Cache-Control: public, max-age=31536000, immutable` — a new file is a new id — the content type recorded at upload, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`) and the **Staff-only** `GET /api/admin/v1/website/hero/media/{id}` (the editor's thumbnails and preview, any recorded picture including one no slide uses yet; `Cache-Control: private, max-age=3600`). The Admin uses its own route because a deployed Admin proxies only `/api/admin/v1/*` to the API (`BHA-ADMIN-PROXY-001`) and its Staff cookie has `Path=/api/admin`; the public route is reachable by a random, unlisted id before a Save publishes the picture (unguessable; it is only the picture, never the texts). The Customer draws pictures with `next/image` `unoptimized` (the optimizer would fetch from the API host); the Admin hint recommends 1920×900 and ≈ 500 KB because pictures are served as uploaded, not resized. In a *direct* (non-proxied) Admin on another registrable domain than the API the `SameSite=Strict` cookie would not be sent on an `<img>` request and thumbnails would not show; local development (same site, different port) and the proxied deployment are fine.
- **Validation is by the bytes** (`HeroImageInspector`, no dependency): JPEG (markers to the end-of-image marker), PNG (chunks, CRCs, `IEND`, no trailing data, the pixel data must inflate to the rows the header promises), still WebP (RIFF size, `VP8`/`VP8L`/`VP8X` header). Not accepted: SVG, GIF, animated WebP/APNG, markup, a truncated or mislabelled file, > 10 MB (enforced while reading, not on the declared length), < 320×160, > 8000 px a side or > 40 megapixels. **Limit:** it does not decode JPEG/WebP pixels, so a file whose container is sound but whose compressed data is damaged is accepted (ImageSharp's licence is not free for commercial use and SkiaSharp brings native binaries; a decoder is a possible later step). JPEG extra data after its end marker is allowed (camera extensions) and cannot run: fixed type + `nosniff`.
- **Never deleted:** replacing, deleting a slide, Cancel, a failed Save never touch a recorded file; there is no garbage collection (unused uploads stay in the library, newest first). A Save refuses a picture whose row or file is missing (`hero-media-missing`); the filesystem is outside the database transaction by design. An upload whose row insert fails removes only that just-written, never-referenced file.
- **A new picture never inherits another's credit:** the public slide carries `seedFile` only for a built-in photograph; the credit line and the credits page are looked up by it.

## 4. API

| | Route | Notes |
|---|---|---|
| Admin read | `GET /api/admin/v1/website/hero` | settings, per-language texts, slides, every picture (library), `revision`, `version`; `no-store` |
| Admin write | `POST …/hero/save` | `{expectedRevision, fontKey, autoplayEnabled, intervalSeconds, texts, slides:[{id, mediaId, focalPosition, alt, caption}]}`; list order = slideshow order |
| Admin upload | `POST …/hero/media` | `multipart/form-data`, part `file` |
| Admin picture | `GET …/hero/media/{id}` | the bytes of a recorded picture, for thumbnails and preview; Staff session + permission |
| Public read | `GET /api/v1/website/hero?locale=` | `{revision, locale, generatedAtUtc, fontKey, autoplayEnabled, intervalSeconds, title, description, primaryAction, secondaryAction, slides:[{id, imageUrl, seedFile, focalPosition, alt, caption}]}`; `no-cache` + ETag (304); no Staff id, draft, path or administrative field |

Access is the other website routes': Staff session + `WebsiteSettingsManage` (401/403), HTTPS, exact Origin, closed under LocalGate. **The only exception to "Staff writes are JSON only" is the upload action**, marked `[AllowStaffMultipartUpload]`: it takes `multipart/form-data` *instead of* JSON (415 for anything else), after the permission and Origin checks; every other Staff route — the hero save, menus, languages, translations — still answers multipart with 415. `SuppressConsumesConstraintForFormFileParameters` keeps MVC from answering a wrong body type before the boundary filter does. Request size limit 11 MB; the file's own limit is 10 MB, answered as `400 hero-image-too-large`. A body the framework cannot read at all (far over 11 MB, or not valid multipart) fails model binding; on the upload action only, that is turned into `400 hero-upload-unreadable` with field `file` (every other route keeps the framework's default answer). The Admin also checks type and size before it sends anything.

**Save** runs in the website advisory-lock transaction: stale `expectedRevision` (hero version plus every text row's version, so a text edited on the Translations screen also makes a save stale) → `409 stale-version`; validation → `400` with a `hero-*` code and the field (`slides[2].alt.vi`); then replaces the slides, writes/clears text rows, drops the texts of removed slides, bumps the version. A save that changes nothing writes nothing. Codes: `hero-font-invalid`, `hero-interval-invalid`, `hero-slides-count`, `hero-duplicate-slide`, `hero-media-missing`, `hero-focal-invalid`, `hero-text-invalid`, `hero-text-required`, `hero-unknown-locale`, `hero-image-{empty,too-large,unsupported,corrupt,dimensions}`, `hero-upload-unreadable`, `hero-storage-not-configured`.

**Limits (so the fixed-height banner never overflows):** title 80, description 160, button labels 24, picture caption 60, alt 200 characters, plain text (no `< >`, no control characters or line breaks). 1–10 slides.

## 5. Customer

- `getHeroSnapshot` (server, `no-store`, last good copy per language, `null` on a first failure) feeds `HomeHeroCarousel` as `initial`. With `null` the frame, the texts from the language catalog and the real search form render and there is simply no picture; the carousel then picks up the hero as soon as a check succeeds.
- `useHeroSnapshot` reuses the menu's loop (`createMenuPoller`, now generic): every 10 s while the tab is visible and the hero is mounted (the home page; no other page polls), on focus and on visibility, one request at a time, the one in flight aborted on a language change or unmount; an answer replaces the hero only if it is for the language on screen and newer by the API's clock; **an answer with the same revision replaces nothing**, so a quiet poll re-renders nothing and re-arms no timer. A failed check keeps the last good hero. No `router.refresh()`, so the search draft, holds and sessions are untouched.
- The slide on screen is held **by id** (`resolveActive`): reordering keeps it, deleting it lands on the slide that took its place (never past the end, never a black frame). **One timer** (`scheduleAutoplay`) is keyed on the slide, the interval, the Admin switch and the *ids* of the slides — not on the array — so a text or font change re-arms nothing. Autoplay runs only when the Admin switch is on **and** none of the baseline reasons to stop apply (reduced motion, pointer or focus inside, hidden tab, swipe, the visitor's pause); one slide has no timer, no dots and no arrows; with the switch off the visitor's pause button is hidden and manual controls (arrows, dots, keyboard, swipe) still work; switching it back on does not clear the visitor's own pause.
- Font: the Admin's token maps to a stack the page already has (`lib/hero/hero.ts`): theme default (Poppins), Be Vietnam Pro (`--font-header`), a system sans and a system serif that name Noto/DejaVu so Vietnamese and French letters render; applied to the title and description only. The Admin preview loads Poppins and Be Vietnam Pro with `next/font` and repeats the table (a test reads the Customer file and the API's list and fails on any difference).

## 6. Admin editor behaviour

Position is buttons (Lên/Xuống), usable on a phone and by keyboard; no drag-and-drop. Bad texts, interval or font are explained beside the field and block Save; a server refusal naming a field selects that slide and language. A stale save keeps the draft; "tải giá trị mới nhất" loads the server's revision but keeps the draft, and says Save will replace the server's hero. A lost answer — of a Save or of an upload — is never retried: the screen locks, reads the server, and for a Save compares the stored hero with what was sent. Leaving with unsaved changes asks (tab close, in-app links, Sign out). `useLeaveGuard` is shared with the menu screen.

## 7. Not done / limits

No page builder, media library beyond "choose a picture the site already has", crop editor, video, schedule, version history UI or drag-and-drop; no per-slide texts or buttons (title, description and buttons are shared); no colour/size/layout controls; no focal-point editor (a new picture is centred; the seeded ones keep theirs); no garbage collection of unused uploads; JPEG/WebP pixels are not decoded (§3); uploaded pictures are not resized (large files are served as they are; keep them near 1920×900); the old `content.hero.*` keys remain in the catalog unused.
