## 2. Phase 1 — shared advisory-lock coordinator (commit `9d198a0`)

Introduced `AdvisoryLockCoordinator` (`Infrastructure/Persistence/AdvisoryLockCoordinator.cs`):
`RoomTypeScopeLockKey`/`InventoryLockKey` (`IComparable`), `LockPlan`,
`LockPlanBuilder` (fluent `WithReservationUnit(s)`/`WithRoomTypeScope`/
`WithInventory`), and a static coordinator with `AcquireKeyAsync`/
`AcquireAsync` that dedupes and sorts each lock class before acquisition
inside one explicit transaction. Refactored every existing advisory-lock
writer (`BookingHoldCreationStore`, `BookingHoldConfirmationStore`,
`BookingHoldCancellationStore`, `ReservationCancellationStore`,
`DailyInventoryControlStore`/`DailyInventoryControlCommands`) onto the
shared coordinator without changing prior lock semantics or key derivation.
7 new integration tests (`AdvisoryLockPlanTests`, no database required —
pure lock-plan construction/ordering evidence).

## 3. Phase 2 — `RoomOccupancySegment` schema and migration 8 (commit `cf0ce60`)

Added `TheBha.Domain/Scheduling`: `RoomOccupancySegmentType`
(`ReservationAssignment`/`OperationalBlock`),
`RoomOccupancySegmentStatus` (`Effective`/`Cancelled`),
`RoomOccupancySegmentAuditEventType`, `SchedulingFieldLimits`,
`SchedulingGuard` (internal), `RoomBlock`, `RoomOccupancySegment` (public
constructor, `Covers(date)`, `Cancel()`), `RoomOccupancySegmentAudit`
(immutable, no mutators). EF configurations wire `xmin`-based optimistic
concurrency (`IsRowVersion()` on a shadow `uint`, not the obsolete
`UseXminAsConcurrencyToken()`), composite alternate-key foreign keys to
`PhysicalRoom`/`ReservationUnit`/`RoomBlock` via `(PropertyId, Id)` for
same-Property database enforcement, and CHECK constraints. `PhysicalRoom`
gained its own `(PropertyId, Id)` alternate key to support this.

Migration 8 (`20260826035254_PhysicalRoomScheduleAvailabilityAuthority`)
enables `btree_gist`, adds the three tables, and creates exactly two
PostgreSQL exclusion constraints
(`EX_RoomOccupancySegments_EffectiveRoomOverlap`,
`EX_RoomOccupancySegments_EffectiveUnitOverlap`) plus two `DEFERRABLE
INITIALLY DEFERRED` constraint triggers — booked-night coverage
(`thebha_check_booked_night_coverage`, `SQLSTATE XBHA1`) and
unit-commitment consistency (`thebha_check_unit_commitment_consistency`,
`SQLSTATE XBHA2`) — so a transaction may pass through a transient
intermediate state as long as the final committed state satisfies both
invariants. `Down()` is guarded (only succeeds while all three tables are
empty) and drops the trigger functions only after all table drops, since an
earlier ordering attempt failed with "cannot drop function because other
objects depend on it" (the table's own trigger still referenced it).

19 new tests: 14 `RoomOccupancySegmentInvariantTests` (exclusion/trigger
behavior against real PostgreSQL) and 5
`PhysicalRoomScheduleAvailabilityAuthorityMigrationTests` (guarded
downgrade, empty-state 8→7, reapply 7, catalog-data preservation). Fixed
three pre-existing tests for the new migration count/fixture shape
(`BookingHoldApiTests`, `PropertyInventoryPersistenceTests`,
`CommercialCommitmentV2MigrationTests`).

## 4. Phase 3 — assignment-aware availability and cancellation cleanup (commit `490f65c`)

Added `Application/Properties/PhysicalCapacityFormula.cs` (pure static
`UsablePhysicalCapacity`/`ControlledCapacity`/`AvailableToSell`) and
`Infrastructure/Persistence/PhysicalCapacityDataLoader.cs` (blocked-room
counts, attributed reservation demand). Rewired `AvailabilitySearch`,
`AvailabilityDataSource`, `BookingHoldCreationStore`, and
`DailyInventoryQueries` onto the shared formula/loader:
`UsablePhysicalCapacity = max(0, BaseInventory - OperationalBlockedRooms)`
before the existing `ControlledCapacity`/`SellableLimit`/`IsStopSell`
clamp; nightly demand attributed to exactly one RoomType bucket (sold
RoomType if unassigned, actual assigned `PhysicalRoom`'s RoomType if an
`Effective ReservationAssignment` covers that night — never both).
Assignment *mutation* is validated against raw `UsablePhysicalCapacity`
only, never `ControlledCapacity`/`SellableLimit`/`IsStopSell` (those govern
acceptance of new commercial demand, not where already-committed demand
physically sits).

Extended `ReservationCancellationStore` to atomically cancel any
still-`Effective` assignment segments of a cancelled Reservation's Units in
the same transaction, writing audit rows tagged
`system:reservation-cancellation`
(`Domain/Scheduling/SystemActorReferences.cs`).

**Bug found and fixed during this phase:** an EF Core query shaped as
`segments.Join(rooms.AsNoTracking(), ..., (segment, room) => new { Segment
= segment, ActualRoomTypeId = room.RoomTypeId })` silently failed to
persist `segment.Cancel()` mutations at `SaveChangesAsync` — no error, just
a deferred `XBHA2` trigger violation at commit because the segment was
never actually cancelled. Root-caused by elimination and fixed by loading
segments as a plain tracked list (no join), then separately loading a
`Dictionary<Guid, Guid>` of `PhysicalRoomId → RoomTypeId` via a second
`AsNoTracking()` query, combining in C#. Owner/OC mandated this two-step
load pattern for all subsequent mutation code in the Phase 4 authorization.

8 new `AssignmentAwareAvailabilityTests`, 1 new `AvailabilitySearchTests`
case.

## 5. Phase 4 — safe internal assignment/block mutation commands (commit `f58aa1e`)

Added the internal application/persistence mutation boundary: `Application/Scheduling/RoomOccupancyDtos.cs`,
`AssignmentMutations.cs`, `BlockMutations.cs` (commands/DTOs/result types);
`Infrastructure/Persistence/RoomOccupancySegmentMutationSupport.cs`
(internal shared helper: `xmin` read via `GetVersion`, DTO projection,
`ExactlyPartitions` no-gap/no-overlap coverage validation,
`TryCommitAsync` error mapping, `ValidateFinalCapacityAsync`);
`AssignmentMutationStore.cs`/`OperationalBlockMutationStore.cs`
implementing `IAssignmentMutationStore`/`IOperationalBlockMutationStore`,
registered in `InfrastructureServiceCollectionExtensions`.

Delivered operations: assignment create (same- or cross-RoomType, the
latter gated by mandatory `AuthorizationEvidence`/`Reason`), split,
move/reassign, atomic batch move/swap (one combined final-state capacity
evaluation per batch — never validated sequentially), unassign/cancel;
OperationalBlock multi-room creation, split, move, cancel. Every mutation
requires a non-empty `ActorReference`. All PostgreSQL writers route through
the Phase 1 `AdvisoryLockCoordinator`'s fixed class order. `23P01`
exclusion violations are mapped only by the two approved constraint names,
and `XBHA1`/`XBHA2`/foreign-key violations by exact SQLSTATE, to safe
`SegmentMutationResult` messages — no raw PostgreSQL/Npgsql text is ever
exposed.

**Bugs found and fixed during this phase:**

- `SupersedeAsync` initially built `RoomOccupancySegmentDto` objects (which
  read `xmin`) inside the same try block as the entity mutations, before
  `TryCommitAsync`/`SaveChangesAsync` — `xmin` was still the uninitialized
  default for newly-created segments. Fixed by collecting the tracked
  `RoomOccupancySegment` entities during the mutation phase and projecting
  to DTOs only after `TryCommitAsync` returns success.
- A deadlock/concurrency test reused a single `IAssignmentMutationStore`
  (one DbContext) across two concurrently-awaited tasks — EF Core
  `DbContext` is not safe for concurrent operations, causing "Connection
  already open." Fixed by creating two separate store instances (`storeForAB`,
  `storeForCD`), each with its own DI scope/DbContext.
- Minor test-fixture fixes: `hold.Confirm(...)` used instead of a
  hand-constructed `Reservation` to avoid double-counting demand from an
  unconfirmed Hold; a confirmation-number generator switched to a hashed
  8-char suffix to stay under the 32-character field limit for long test
  slugs; a test needing a second `ReservationUnit` had its fixture's
  `unitsA` parameter corrected from 1 to 2.

29-item mandatory test matrix delivered as 21 tests in
`AssignmentMutationStoreTests.cs` and 5 in
`OperationalBlockMutationStoreTests.cs` — full acceptance mapping in
`docs/reports/PMS-BE-001.2-completion.md`, not repeated here.

End-of-phase verification: 244/244 unit tests, 317/317 PostgreSQL
integration tests, concurrency-sensitive subset re-run 3× with no
