## 4. Gate 1 — Khóa topology FE ↔ BE

Control Tower chốt và ghi lại một quyết định duy nhất cho:

- local origin của Customer Web và API;
- production origin/domain dự kiến;
- cookie `SameSite`, HTTPS, CORS allowlist;
- `credentials: "include"` cho cookie session;
- cách lấy và refresh request token từ `GET /api/v1/auth/csrf`;
- cách giữ `X-Booking-Access-Token` của guest.

### Quy tắc bảo mật

- Không ghi guest access token vào log, URL, query string hoặc analytics.
- Không giả định có thể lấy lại token: backend chỉ trả raw token ở response
  `201` đầu tiên; idempotent replay không trả token.
- Không dùng email/contact làm ownership.
- Không tự thêm JWT; backend hiện dùng secure HttpOnly customer cookie.
- Nếu chưa khóa được nơi lưu guest token an toàn, chỉ làm read-only
  availability trong ngày và hoãn booking mutation.

## 7. Chuẩn bị task kế tiếp — Booking mutation

Chỉ thiết kế contract/state machine, chưa bắt buộc code trong cùng ngày:

```text
Availability result
  → Create Hold (Idempotency-Key + CSRF)
  → Persist holdId/expiresAt/guest token safely
  → Countdown from server ExpiresAtUtc
  → Confirm Hold
  → Read Reservation
  → Optional cancellation
```

Phải xử lý rõ:

- `201 Created` so với `200 Replayed`;
- `400`, `401`, non-disclosing `404`, `409`;
- mất response `201` của guest Hold;
- Hold hết hạn đúng boundary;
- không reprice sau khi Hold đã tạo;
- không phát lại mutation do React rerender/double submit;
- idempotency key ổn định cho một user intent, nhưng đổi cho intent mới.
